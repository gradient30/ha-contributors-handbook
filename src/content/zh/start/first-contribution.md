# 你的第一次贡献 {#your-first-contribution}
你的第一次贡献不需要很大。一处错字的修改、十条字符串的翻译、在[论坛](https://community.home-assistant.io/)上回答一个问题：这都是实际的贡献，并且能教你项目是如何运作的。从小处开始，完成一次循环，下一次会更容易。  

大多数帮助的方式根本不涉及编写代码，因此它们排在本页的前面。每条路径都会说明你需要哪个账号，并链接到包含具体步骤的页面。

## 在你开始之前 {#before-you-start}
无论你选择什么，有两件事是相同的：

- **阅读 [行为准则](/start/code-of-conduct)。** 它很简短，并且适用于任何地方。
- **知道去哪里提问。** 你不需要许可就可以开始，但知道遇到问题时该去哪里会很有帮助。[问答区](https://www.home-assistant.io/join-chat/) 是提问的最快地点。代码遇到问题？在 [一般编码支持](https://discord.com/channels/330944238910963714/1257019582112334014) 提问。查看 [我们的讨论位置](/start/where-we-talk) 来找到适合你领域的地方。

许多路径使用 GitHub。从未使用过，或者从未理解过吗？先阅读 [使用 GitHub，无需成为开发者](/start/github)。它解释了相关术语，并指导你在浏览器中进行更改。

## 你会说另一种语言 {#you-speak-another-language}
Home Assistant 由使用它的人翻译。如果你是母语者，你可以在几分钟内开始。界面在你的浏览器Lokalise中完成翻译。

- **你需要：** 一个免费的 [Lokalise](/glossary/lokalise) 账户。加入项目时，Lokalise 会让你创建一个账户。
- **从这里开始：** [你的第一次翻译](/translate/first-contribution)。

想让 Assist 在你和它交流时理解你的语言吗？这项工作在 GitHub 的 YAML 文件中通过 pull request 完成，因此你需要一个免费的 [GitHub](https://github.com/signup) 账户。先从 [语音](/translate/voice) 开始。

## 你喜欢写作 {#you-like-to-write}
home-assistant.io 上的文档由社区编写。从你的浏览器直接修复一些小问题。

- **你需要：** 一个免费的 [GitHub](https://github.com/signup) 账户。
- **从这里开始：** [你的第一次文档修正](/writing/first-contribution)。

### 你的设计 {#you-design}
流程、界面、组件和 UI 文本。你不需要编写代码就可以帮助塑造 Home Assistant 的工作方式。

- **你需要:** 一个 [Discord](https://www.home-assistant.io/join-chat-design) 账户以便在 [**#designers**](https://discord.com/channels/330944238910963714/1463606665311158284) 中与设计师见面，以及一个免费的 [GitHub](https://github.com/signup) 账户以便在讨论和问题中分享提案。
- **从这里开始:** [你的首次设计贡献](/design/first-contribution) 。

### 你喜欢帮助别人 {#you-like-helping-people}
在论坛和 Discord 上回答问题，欢迎新成员，组织聚会，或者帮助分享新闻。

- **你需要:** 一个 [社区论坛](https://community.home-assistant.io/) 的免费账户。
- **从这里开始:** [回答你的第一个问题](/community/first-contribution)。

### 你想在别人之前进行测试 {#you-want-to-test-before-everyone-else}
每个月，下一个版本的测试版会在正式发布前一周推出。运行它并报告问题可以防止漏洞进入他人的使用环境。

- **你需要：** 一个 Home Assistant 安装环境，在这里问题只是小麻烦而不是灾难，以及一个免费的 [GitHub](https://github.com/signup) 账户来报告你发现的漏洞。
- **从这里开始：** [加入测试版](/releases/first-contribution)。

你是否有需要测试 pull request 的设备或浏览器？某些区域允许你在更改合并之前进行尝试，而无需进行构建。请参阅 [试用前端 pull request](/frontend/development/builds#try-out-a-pull-request) 和 [测试 Android pull request 构建](/companion/android/get-started#test-a-pull-request-build)。然后在 pull request 上留言，说明你发现的情况。"我用我的设备尝试过，它可以正常工作" 是一个有用的评测。

### 你想分享数据 {#you-want-to-share-data}
在你自己的 Home Assistant 中开启分析功能，帮助项目了解正在使用哪些集成、版本和安装类型。除非你开启，否则不会共享任何信息。

- **你需要:** 一个 Home Assistant 安装。不需要账户。
- **从这里开始:** [分享你的分析数据](/data/first-contribution)。

## 正确报告一个错误 {#report-a-bug-well}
出现问题了吗？一个带有清晰重现步骤的问题可以为维护者节省大量时间。[报告错误](/start/report-a-bug) 会告诉你应该使用哪个仓库、表单中需要填写的信息，以及在哪里可以找到他们所需的日志和版本。

- **你需要:** 一个免费的 [GitHub](https://github.com/signup) 账户。

### 报告安全问题 {#report-a-security-problem}
发现了可能危及人们家庭的情况？不要提交公开问题：问题是公开的。请私下报告，这样问题可以在细节公开前得到修复。[报告漏洞](/security/report-a-vulnerability)会告诉你如何操作，以及需要包含哪些信息。

- **你需要：** 一个免费的 [GitHub](https://github.com/signup) 账户。

### 你构建了值得分享的东西 {#you-built-something-worth-sharing}
一个在你家中运行良好的自动化也可以帮助别人。将其变成蓝图并分享出来。创建了一个仪表板卡片、主题或你自己的集成？在市场中发布是推荐的第一步：你可以获得经验，并且可以更快地迭代。你不需要在 Home Assistant 仓库中有一个 pull request：它存在于你自己的仓库中。

- **你需要：** 一个免费的 [GitHub](https://github.com/signup) 账户。对于蓝图，不需要编程。
- **从这里开始：** [分享你的第一个蓝图](/marketplace/first-contribution)。

## 使用代码 {#with-code}
这些路径最终都会在 GitHub 上形成一个 pull request，并在适用 [Contributor License Agreement](/start/first-contribution#the-contributor-license-agreement) 的仓库中。为自己构建应用是个例外：你可以从你自己的仓库发布。每个首次贡献页面都会告诉你如何设置开发环境。

### 你编写 Python {#you-write-python}
Home Assistant Core 是 Python 的核心应用：自动化引擎和成千上万的集成。从一个小的错误修复或缺失的测试开始。

- **从这里开始：** [你对 Core 的第一份贡献](/core/first-contribution)。

### 你编写 TypeScript 或处理网页界面 {#you-write-typescript-or-work-on-web-interfaces}
前端包含你在浏览器和伴侣应用中看到的所有内容：仪表板、设置和对话框。它使用 Lit 和 TypeScript 构建。

- **从这里开始：** [你的第一个前端贡献](/frontend/first-contribution)。

Android 和 iOS 的伴侣应用（也适用于 macOS、Wear OS 和 Apple Watch）使用 Kotlin 和 Swift 编写。

- **从这里开始：** [你的第一个伴侣应用贡献](/companion/first-contribution)。

## 你在 Linux、嵌入式系统或容器上工作 {#you-work-on-linux-embedded-systems-or-containers}
Home Assistant OS 和 Supervisor 安装、更新并运行所有内容。那部分工作涉及 Linux、Docker、开发板以及 Python。

- **从这里开始：** [你对 Supervisor 的第一个贡献](/os/first-contribution)。

### 你想打包软件 {#you-want-to-package-software}
应用程序（以前称为插件）是 Supervisor 在 Home Assistant 旁边运行的容器，比如数据库或 Zigbee 桥。你可以自己构建一个，无需任何人的批准。

- **从这里开始：** [你的第一个应用](/apps/first-app)。

## Contributor License Agreement {#the-contributor-license-agreement}
Home Assistant 的代码仓库，如 Core、前端、伴侣应用、Supervisor、Home Assistant OS 和官方应用，会要求你签署 [Contributor License Agreement](/start/licensing)。第一次在其中一个仓库中打开 pull request 时，机器人会发表评论并附上链接。你只需执行一次，这也会涵盖你未来的贡献。在你签署之前，你的 pull request 无法合并。

不涉及代码的路径不需要签署：翻译、修改文档、贡献语音句子、回答问题、测试 Beta 版本，以及分享分析数据。

## 接下来会发生什么 {#what-happens-next}
打开了 pull request？[pull request和审查](/start/pull-requests) 会告诉你接下来会发生什么。审查需要时间，因为 pull request 比审查者多。请耐心，继续前进。一旦完成，[作为贡献者的成长](/start/grow) 会显示你可以去的下一步方向。
