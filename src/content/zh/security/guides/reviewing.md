## 从之前的错中吸取教训 {#learn-from-what-went-wrong-before}

[过去的建议](/security/reference/advisories) 103. Home Assistant的[过去的建议](/security/reference/advisories)是那里最好的培训材料。 他们不断回到同样的主题:

- ** 作为 HTML 提供的名称。 ** 存储 XSS通过一个图形工具提示和历史图表卡中的实体名称,并通过地图卡中的设备名称.
- ** 不安全的URL。 ** 通过`javascript:`完全收购 登录回调中的 URL, 以及 Core 中部分服务器侧请求的伪造 。
- ** 端点没有登录。 ** 集成的提醒面板状态, 以及 Home Assistant 的用户账户, 任何人都可以在本地网络上读取 。 未认证的端点应用软件,通过主机网络模式可到达本地网络.
- ** 证书检查。 ** SSL在Core及其使用的库中验证出错的请求。
- ** 公司应用程序自行操作。 ** 链接和其他让应用程序在不询问的情况下向服务器发送标签扫描,位置,或动作的应用程序,以及到达JavaScript桥的帧中的网页.
- ** 该项目自己的工具。 ** GitHub 中的表达式注入 行动

[参考页](/security/reference/advisories)将每一个咨询按种类分组, 并有教训和链接 GitHub 的细节。 阅读其中的几个会改变你读代码的方式.

### 数据 {#data}

- 证书在配置条目的`data` 中,没有别的地方。
- 诊断器会将所有隐私都剪掉 检查测试中的快照: 您能确切看到用户共享什么 。
- 日志行不包含密码,令牌,或➢全键.
- 来自设备或服务的数据不会传递给`eval()`,`exec()`,或者一个 shell.

请不要要求额外检查某个动作的计划已经验证的字段 。 在操作员运行前检查一下 要求检查数据从哪里跳过计划,或者变成不太安全的东西.

### 网络 {#network}

- 集成使用Home Assistant的共享网页会话.
- 证书检查在默认情况下进行. 如果有关闭它们的选项,则由用户选择,关闭不是默认.

### 前端 {#frontend}

- 名称,属性,以及其他数据通过Lit模板到达页面,而不是`innerHTML`或HTML字符串.
- 如果库需要 HTML 字符串,则未信任的部分会通过 `filterXSS`.
- 来自数据的URL通过`sanitizeHttpUrl`或`sanitizeLinkUrl`.
- `<ha-markdown>` 和 `allow-svg` 只让信任的内容 。

### 依赖 {#dependencies}

- 新库符合 [依赖性透明度](/core/quality-scale/dependency-transparency) 规则 。
- 将更新改为上游diff,并查看检查要求工作流程的评论. 见[依赖性和供应链](/security/guides/dependencies).

### 应用程序 {#apps}

- 更改某物的应用程序的每个端点都有登录,或者只通过入侵接受Supervisor. 听内部地址不是登录 见[如果他们是安全的应用程序](/security/guides/apps).

### 伴侣应用 {#companion-apps}

- 一个新的链接, 意图, 或快捷键, 可以更改服务器上的东西 。
- 新的Android组件不导出,除非另一个应用程序必须到达它.
- 给 JavaScript 桥的邮件只来自服务器的主框, 并且没有从信件中得出的值成为代码 。 见[安全附带应用程序](/security/guides/companion-apps).

### 工作流量 {#workflows}

- 新的行动是建立在承诺的基础上的。
- 不仍有 `${{ }}` 外部数据的表达式, 如分支名称或标题, 在 `run:` 脚本中 。 见[以前发生什么了](/security/guides/dependencies#what-went-wrong-before).
- 权限小于任务允许的大小,并使用 `persist-credentials: false` 退出 。
