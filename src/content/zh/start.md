# 开始贡献 {#get-started}
Home Assistant 是由成千上万的人共同建设的。有些人编写 Python 或 TypeScript，很多人没有。他们翻译界面、修正文档中的一句话、设计更好的对话框、在 [论坛](https://community.home-assistant.io/) 帮助别人，或者测试 beta 版本。每一项都是贡献，每一项都让 Home Assistant 为数百万家庭变得更好。

这个区域适合所有想要参与的人。这里解释了项目如何组织、人们在哪里交流，以及你的第一次贡献如何从想法变为合并。

## 从这里开始 {#start-here}
1. [你的第一次贡献](/start/first-contribution)：选择一条适合你技能的路径，然后迈出第一步。大多数路径不需要编写代码。
2. [使用 GitHub，不需要成为开发者](/start/github)：在 GitHub 上你会遇到的词语，以及如何在浏览器中进行更改。
3. [我们讨论的地方](/start/where-we-talk)：Discord，社区论坛，以及 GitHub，以及每个领域的人在哪里可以找到。

## 指南 {#guides}
- [报告错误](/start/report-a-bug)：使用哪个仓库，错误报告表单要求什么，以及在报告之后会发生什么。
- [pull request和审查](/start/pull-requests)：如何打开一个便于审查的pull request，以及在任何仓库中打开它之后会发生什么。
- [作为贡献者成长](/start/grow)：在你的第一个pull request之后会发生什么，从审查和分类到拥有一个集成或承担一个角色。

## 背景 {#background}
在你第一次贡献之前，你不需要阅读这些内容。这些内容在你想了解事情是如何运作时会有帮助。

- [项目如何组织](/start/organization)：Open Home Foundation、其商业合作伙伴、代码仓库以及维护这些仓库的人员。
- [从想法到发布](/roadmap/how-it-works)：大型工作是如何规划的，从功能请求到发布，以及你可以从哪里参与。
- [我们的原则](/start/principles)：Home Assistant所代表的意义，以及这对你的工作意味着什么。
- [使用AI工具进行贡献](/start/ai-tools)：仓库为代理提供的说明和技能、常见任务的工作流程，以及你需要自行检查的内容。
- [AI政策](/start/ai-policy)：在你贡献时可以和不可以如何使用AI工具。
- [许可和CLA](/start/licensing)：许可协议，以及你在代码仓库中一次性签署的Contributor License Agreement。
- [行为准则](/start/code-of-conduct)：我们如何相互对待，以及如何报告问题。

## 想知道这一切是如何协同工作的吗？ {#want-to-know-how-it-all-fits-together}
[架构](/architecture) 部分解释了 Home Assistant 的各个部分如何协同工作，从[整体概览](/architecture/big-picture)到[决策是如何做出的](/architecture/decisions)。你在第一次贡献之前不需要阅读它，但在深入了解之后会很有帮助。

## 与谁联系 {#who-to-talk-to}
- 不确定从哪里开始？可以在 [Home Assistant Discord](https://www.home-assistant.io/join-chat/) 提问。那里的人员对这个问题非常熟悉。加入后，关注 [公开构建](https://discord.com/channels/330944238910963714/1257022408385237072)，这是面向贡献者的公告频道，以了解项目的最新动态。
- 关于具体变更的问题？在 GitHub 的 issue 或 pull request 中提出，这样了解该代码的人就能回答你。
- 本网站的每个领域都有自己的“与谁联系”部分，列出了对应工作的沟通渠道。
