# 用户界面文本 {#ui-text}

每个标签,按钮,错误,和空状态都是设计决定. 良好的UI文本帮助人们理解正在发生的事情,以及下一步要做什么,往往不让他们注意到.

在设计屏幕时,以及在构建屏幕时,您会写UI文本:在前端,在整合的`strings.json`中。 同一准则适用于两地。

## 的实质性对话 {#how-home-assistant-talks}

UI 文本跟随 Home Assistant 的 [个性](/brand/personality) 。 在界面中,五个特征出现在小事物中:

- **谐音**:在自己的层面上与人见面,永远不要对他们低调。 它显示了一个错误是如何解释的.
- 说出你的意思 不要把复杂性隐藏在虚假的简单背后,或者假装限制不存在.
- ** 支持**:引导人们前进,而不是接管。
- ** 这项力**:相信掌握和透明的人。 没有 这项术
- **独立**:Home Assistant不需要听起来像一个既定的技术品牌.

在 [声音与语气](/brand/voice-and-tone) 中, 如何在界面外发出相同的声音, 如文档和社区回复 。

## 样式 {#style}

- 用美式英语写作,以友好和信息语气写作.
- 敷衍人言,以"汝"与"汝"合之处.
- 简洁明了. 使用活动的声音 。
- 为技术人员和非技术人员写作。 避免一个熟悉的家庭自动化术语的术语。
- 对标题,标题,按钮,标签,以及界面中的其他所有内容使用句子大小写:"创建新自动化",而不是"创建新自动化". "DEVice设置",不是"DEVice设置".
- 全文写"Home Assistant". 从来没有"HA"或"HAS"。
- 使用"类似"或"例如"来代替拉丁语缩写.
- 在列表中使用牛津逗号 。
- 不要用所有的盖子来强调。
- 在集成文本中,将类似代码的值包裹起来,如实体ID和文件名称,用回击. 如Z-Wave和MQTT一样,写出品牌和协议名称,没有背书。

## 单词 {#words}

- 一件东西有一个名字。 [,](/glossary) 列出 Home Assistant 使用的术语, 以及您不应使用过的旧名, 如 [动作](/glossary/action) 的“ 服务 ” 。
- 产品术语在句子中为小写:自动化,实体,设备.
- 与使用 Home Assistant 的人交谈时, 说"整合", 不是"组件" 。
- 选一个和人们做的吻合的词. "乔因"或"Apply"可以比"Group"多说.

## 翻译 {#translations}

所有UI文本都译为数十种语言,所以必须以一种翻译者可以合作的方式写成:

- 人们看到的每条弦都通过翻译系统。 代码本身没有文本 。
- 对值使用占位符,并保持句子完整。 从不粘合 翻译块在一起。
- 提供有清晰密钥名称和占位符名称的翻译背景。
- 在集成中,当同一个文本存在时,再使用一个通用的翻译密钥.

有细节  L1}文档中的[样式指南承担起](/writing/reference/style)也适用于UI文本,比如写“选择”而不是“单击”。
